# Quickstart: Validating the Screenplay-Based Quality Engineering Framework

This guide describes how to prove StageCraft works end-to-end, once implemented per this plan.
It does not include implementation code — see `tasks.md` (generated by `/speckit-tasks`) and the
actual `src/`/`tests/` files for that.

## Prerequisites

- Node.js `^22.22.2` (or `^24.15.0`) installed.
- npm (bundled with Node.js).
- Internet access to reach the public demo targets:
  - UI: `https://todomvc.com/examples/react/dist/`
  - API: `https://jsonplaceholder.typicode.com`
- No credentials or API keys required (both demo targets are public and unauthenticated).

## Setup

1. Copy `.env.example` to `.env` (optional — safe defaults are used if omitted) and adjust
   `BASE_URL`, `API_BASE_URL`, or `HEADLESS` if needed.
2. Install dependencies and Playwright browsers:
   ```sh
   npm install
   npx playwright install chromium
   ```
3. Confirm the project compiles under strict TypeScript:
   ```sh
   npm run build
   ```
   **Expected outcome**: exits with code 0 and no TypeScript errors (proves NFR-... type-safety
   and Constitution Principle VII).

## Run the demonstration scenarios

4. Run the UI scenarios only:
   ```sh
   npm run test:ui
   ```
   **Expected outcome**: both UI scenarios pass (SC-002); a Playwright browser session drives
   `https://todomvc.com/examples/react/dist/`.
5. Run the API scenarios only:
   ```sh
   npm run test:api
   ```
   **Expected outcome**: both API scenarios pass (SC-003) against JSONPlaceholder, with no
   browser launched.
6. Run the complete suite:
   ```sh
   npm test
   ```
   **Expected outcome**: all 4 demonstration scenarios pass (User Story 6, Acceptance Scenario
   2).

## Generate and inspect the report

7. Generate/serve the Serenity/JS HTML report:
   ```sh
   npm run report
   ```
   **Expected outcome**: a report is produced/opened under `reports/serenity-js/`. For each
   scenario it must show: scenario title, Actor name, ordered Tasks, Interactions, Questions,
   Assertions, and outcome (FR-011, User Story 5, SC-006). This satisfies the data model's
   Execution Report contract.

## Verify reusability (Constitution Principle IV, FR-014, User Story 4)

8. Inspect the source to confirm at least one Task and one Question are each used by more than
   one scenario — e.g., a shared response-status Question used by both API scenarios, or a
   shared "open the app" Task used by both UI scenarios. There should be exactly one
   implementation of each, referenced from multiple scenario files (see `data-model.md` → Task /
   Question sections for the contract each must satisfy).

## Verify failure diagnostics (NFR-005, User Story 5 Acceptance Scenario 3)

9. Temporarily point `BASE_URL` (or a UI Question's expected value) at something that will fail
   an assertion, re-run `npm run test:ui`, and confirm:
   - the console reporter prints a clear failure with the failing Assertion.
   - the HTML report marks the scenario failed and includes a screenshot captured at the point
     of failure.
   - revert the temporary change afterward so the suite is deterministic again (NFR-004).

## Verify no secrets are committed

10. Confirm `.env` is git-ignored and only `.env.example` (with placeholder/public values) is
    committed; `git status`/`git diff` should show no credential-like values in tracked files.
